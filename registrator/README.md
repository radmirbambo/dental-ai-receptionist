# Агент-регистратор стоматологии (текстовое ядро)

Это **левая зона** архитектуры — мозг агента без голоса. Он умеет вести диалог,
проверять свободные слоты и записывать пациента в базу через function calling.
Голос (STT/TTS/оркестратор) добавляется поверх позже — ядро остаётся тем же.

## Из чего состоит

| Файл | Что делает | Слой архитектуры |
|---|---|---|
| `db.py` | база: слоты, записи, свободное время | PostgreSQL (здесь — SQLite для обучения) |
| `tools.py` | инструменты + их описание для LLM | FastAPI — tools |
| `agent.py` | мозг: системный промпт + **цикл function calling** | LLM-агент |
| `cli.py` | чат в терминале — увидеть цикл своими глазами | — |
| `main.py` | тот же агент по HTTP (сюда потом придёт голос) | FastAPI |

## Как запустить за 3 минуты

```bash
# 1. поставить зависимости
pip install -r requirements.txt

# 2. дать ключ OpenRouter (ключ с https://openrouter.ai/keys)
cp .env.example .env          # затем впиши свой ключ в .env
export $(cat .env | xargs)    # подхватить ключ в окружение

# 3. поговорить с агентом
python cli.py
```

Скажи ему, например: `Здравствуйте, болит зуб, хочу записаться на завтра` —
и смотри, как он проверяет слоты и создаёт запись. База появится в файле
`clinic.db` рядом.

Чтобы вместо терминала поднять HTTP-API (как будет ходить голосовой оркестратор):

```bash
uvicorn main:app --reload
# открой http://127.0.0.1:8000/docs
```

## Где здесь «агентность»

Смотри `agent.py`, функция `run_turn` — это **цикл**:
модель либо отвечает текстом (готово), либо просит вызвать инструмент — мы его
исполняем, кладём результат обратно и спрашиваем модель снова. Крутится, пока
задача не решена. Это и отличает агента от обычного чата.

## Что дальше

1. Поиграй с системным промптом в `agent.py` — почувствуй, как меняется поведение.
2. Добавь инструмент `reschedule_appointment` (перенос) — по образцу `book_appointment`.
3. Оберни `main.py` в Telegram-бота (aiogram), читающего `/appointments`.
4. Только потом — голос: подключи оркестратор (LiveKit/Pipecat), который шлёт
   текст в `/chat`. Ядро при этом не меняется.

## Переезд на PostgreSQL

См. комментарий в конце `db.py` — меняется только слой БД, логика агента не трогается.
